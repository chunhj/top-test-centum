# 1. 프로젝트 개요

## 1.1 프로젝트명

**TOP (Today's Opinion & Poll)**

## 1.2 서비스 유형

실시간 투표 / 랭킹 서비스

## 1.3 프로젝트 목적

TV 오디션 프로그램의 실시간 투표 방식을 참고하여 다음 흐름을 제공한다.

- 사용자가 후보를 선택해 투표한다.
- 투표 완료 후 허용된 구간에서는 실시간 득표 수와 비율을 확인한다.
- 허용된 시간 동안 기존 투표를 다른 후보로 변경할 수 있다.
- 마감 30분 전부터 집계 결과를 비공개 처리한다.
- 관리자는 투표 생성, 시작, 일시정지, 재개, 마감 상태를 관리한다.

UI의 소재는 슬램덩크 등장인물을 활용한 프로토타입으로 구성하되, 실제 공개 서비스에서는 라이선스가 확보된 이미지로 교체한다.

## 1.4 개발 조건

- 1인 개발
- 개발 기간: 2~3주
- 단순 CRUD보다 실시간 투표 서비스의 데이터 정합성, 동시 요청 처리, 상태 전이, 실시간 전달과 실제 운영까지 경험할 수 있는 포트폴리오 수준을 목표로 한다.

# 3. 핵심 정책

## 3.1 투표 시간 정책

투표 상태와 마감 관련 정책은 사용자의 브라우저 시간이 아니라 **서버 기준 시간**으로 판정한다.

| 구간 | 결과 공개 | 신규 투표 | 기존 투표 변경 |
|---|---|---:|---:|
| 일반 진행 구간 | 공개 | 가능 | 가능 |
| 종료 30분 전 ~ 종료 | 비공개 | 가능 | 가능 |
| 종료 후 | 최종 결과 공개 | 불가능 | 불가능 |
| 관리자 일시정지 상태 | 정책에 따라 마지막 화면 유지 | 불가능 | 불가능 |

## 3.2 결과 공개 정책

- 일반 진행 구간에는 실시간 득표 수와 비율을 공개한다.
- 종료 30분 전부터 종료 시점까지는 집계 결과를 공개하지 않는다.
- 종료 후에는 최종 결과를 공개한다.
- 결과 비공개 구간에서도 허용된 정책 범위 안에서는 신규 투표와 기존 투표 변경이 가능하다.

## 3.3 재투표 정책

- 사용자는 허용된 진행 구간에서 기존 선택을 다른 후보로 변경할 수 있다.
- 재투표 후에는 기존 선택이 취소되고 새로운 선택이 최종 투표로 반영되어야 한다.
- 재투표 과정에서 전체 집계가 어긋나지 않아야 한다.

## 3.4 중복 참여 정책

- 한 사용자의 동일 투표 중복 참여를 제한한다.
- 로그인을 강제하지 않는 투표에서는 비회원 참여를 허용할 수 있다.
- 비회원 투표는 실제 사람 기준의 완전한 1인 1표 인증이 아니라 브라우저 식별자를 기준으로 중복 참여를 제한한다.

> "비회원 투표는 브라우저 식별자를 기반으로 중복 참여를 제한합니다."

# 4. 투표 조회 요구사항

## 4.1 진행 중인 투표 목록

사용자는 현재 진행 중인 투표 목록을 조회할 수 있어야 한다.

## 4.2 투표 상세

투표 상세 화면에서는 다음 정보를 확인할 수 있어야 한다.

- 투표 제목
- 설명
- 시작 시각
- 종료 시각
- 투표 방식
- 최대 선택 가능 수
- 후보 목록
- 현재 사용자의 투표 여부
- 현재 투표 진행 상태

## 4.3 실시간 결과 확인

- 결과 공개가 허용된 구간에는 투표 완료 후 실시간 득표 현황을 확인할 수 있어야 한다.
- 결과 비공개 구간에는 득표 수와 비율이 노출되지 않아야 한다.
- 마감 후에는 최종 결과를 확인할 수 있어야 한다.

---

# 5. 서비스 품질 요구사항

- 동시 투표 상황에서도 집계 결과가 정확해야 한다.
- 재투표 처리 중 일부 과정만 반영되는 상태가 발생하지 않아야 한다.
- 빠른 연속 클릭이나 네트워크 재시도로 동일 요청이 반복되어도 투표가 중복 반영되지 않아야 한다.
- 결과 비공개 정책은 화면 표시만 숨기는 수준이 아니라 실제 서비스 응답에서도 지켜져야 한다.
- 관리자 상태 변경은 허용된 상태 전이 규칙 안에서만 동작해야 한다.
- 실제 배포 환경에서 서비스 상태 확인, 로그 확인, 보안 설정이 가능해야 한다.
